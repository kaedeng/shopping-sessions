# Decisions

Tick a box once we're certain.

- [x] **CSV parser:** in-house (`memmap2` + `memchr`, run on the workers in **Parallelism**), not arrow-csv or the Polars reader
- [ ] **Inputs first:** before the parse, read `manifest.json` (the window, which sizes the date table and the day slots), `products.csv` (product → category) and `campaigns.csv` (campaign → index and channel); number the categories in byte order with `unknown` among them, so the `top_category` tie-break is a plain strictly-greater scan
- [ ] **Hot path:** plain Rust over ~1 MB chunks cut at `\n` inside each file; line 1 of each file is the header and is dropped by position only (fixture L3 has a later data row equal to the header text, and that row is data); a last line without `\n` ends at end of file; fixed 32-byte records
- [ ] **IDs:** a `u64` (up to 9 ASCII bytes, 7 bits each, order-preserving); longer or non-ASCII IDs are interned on a slow path, and so is any ID holding byte `0x00`, which would pack like padding; order holds only among packed IDs, so naming a person and the `click_id` tie-break compare bytes when a slow-path ID is involved; every generated ID is a letter plus base36 of a 40-bit value, at most 9 bytes (`generator/src/text.rs`), so the slow path never runs on generated data
- [ ] **Hash and tables:** one multiply of the packed `u64` by an odd constant, its top bits picking the partition and the next bits the slot, with linear probing, as in every prototype
- [ ] **Purchases:** look up the category and parse the price only for `purchase` rows (about 3%); a view or cart needs only a non-empty `product_id`, and its price is ignored whatever it holds; a price is digits only, leading zeros skipped, value 1 to 10,000,000 (`0250` is kept, `00` dropped)
- [ ] **Output:** one Parquet file per worker with arrow-rs (`parquet` crate `ArrowWriter`), uncompressed, no statistics, no dictionary; a hand-written plain-page writer (`out-raw`) is the alternative; no Polars in the binary, so `polars` and `polars-core` can leave `Cargo.toml`; every worker writes its file even when empty, because each table needs at least one `.parquet` (rules; `scripts/run_fixtures.py` fails a folder with none); `day` is `Date32`, days since 1970, `ts.div_euclid(86_400_000)`
- [ ] **Links:** union-find, the larger root linked under the smaller so the root is the person's name (Rem's algorithm with splicing, the fastest sequential variant in Patwary, Blair and Manne, SEA 2010); built on one of the 8 workers while the others parse, and finished before the first person lookup; rows get their person after dedup, in one tight loop per partition against the read-only link table, prefetching 64 rows ahead
- [ ] **Event dedup:** scatter by `event_id` hash into 1,024–2,048 partitions inside the parse loop, dedup each with a small table, keep min `ingest_ts`; validity, including the late check, is one bit set at parse time, so an invalid kept copy is a tombstone; no event is dropped before dedup for being invalid, only for a malformed line or an empty `event_id` (rules, Events 1–2; fixture E5)
- [ ] **Click dedup:** skip it (credit = max, assists = set, copies identical); for the same reason a bad click is dropped at parse, which an event never is
- [ ] **Clicks:** validated at parse (non-empty `user_id`, `ts` in the click window, `campaign_id` in `campaigns.csv`); after the union-find each click gets its person and is scattered into the same person buckets as the events
- [ ] **Sessionize:** scatter survivors by person hash into ~1,024 buckets, `sort_unstable` each on packed `u64` (bucket-local person, ts); radix or vqsort only if profiled; purchases' price and category travel in a per-bucket side list sorted the same way, since views and carts need only `ts`
- [ ] **Attribution:** per person, sessions in order against the person's clicks sorted by `ts`, two pointers over the window [start − 7 days, start], both ends inclusive; credit goes to the latest click, a tie to the smallest `click_id` byte-wise, and no click means `organic`; a count per campaign plus a sparse set of the campaigns with a count above zero gives the assists, each campaign once and `organic` never
- [ ] **Aggregation:** `user_daily` rows stream out per person, since a person's session days only grow; `campaign_daily` comes from per-worker dense arrays `[campaigns + organic][n_days]` summed at the end, with `n_days = day(window_end - 1) - day(window_start) + 1`, which also counts a window that starts mid-day
- [ ] **Timestamps:** date-string lookup table from window start − 8 days to window end + 1 day; a miss makes the `ts` bad, which drops a click but only sets an event's invalid bit (see **Event dedup**); the form is told by content, not length (byte 10 is `T`: F1 or F2; otherwise every byte must be a digit: F3, which with leading zeros can itself be 20 or 25 bytes); the table settles only the date, so hour, minute, second, the offset and its colon are still checked, and the exact ms is compared with the row's window; F3 skips leading zeros and compares its digit count with the row's own window bounds before an 8 + 5 SWAR parse; `ingest_ts` falls back to plain conversion; no calendar code on the hot path
- [ ] **SIMD:** mask-based field tokenizer from day one (AVX2 on the scorer, NEON for local runs), `memchr` only to cut chunks at `\n`; the masks also give row validity (6, 3 or 1 commas per line; quotes only at both ends of a field, checked against the popcount of the quote mask); AVX-512BW is the first experiment after that (intrinsics and target features stable since Rust 1.89); everything else only where a full-size profile points
- [ ] **Layout:** Cargo workspace, one crate per stage (shared types, ingest, links, dedup, sessions, output, the binary); the per-row parse loop stays inside one crate; every alternative in `alternatives.md` sits behind its own Cargo feature, features only add code, and an env var picks when a slot has several compiled in, read once at start to choose a monomorphized path, never a branch per row; LTO on so crate boundaries cost nothing
- [ ] **Parallelism:** 8 workers (from `NCPU`, never more: `--cpus 8` is a time quota), each owning its buffers and pulling tasks largest-first from a shared counter; every stage is data-parallel (file chunks, dedup partitions, person buckets, one output file per worker) with two barriers (after parse, after dedup); the union-find is the only serial job and runs beside the parse as the queue's first task, on one of the 8 workers (a ninth busy thread adds no CPU under the quota, only throttling), which then joins the parse
